**Empirical audit loops** (this run has `--ext empirical`)**:** The `--ext empirical` route adds eight capped loops to the `loops` object — `identification_plan_revision`, `headline_replication`, `replicator_self_refire`, `data_integrity`, `method_check`, `claim_grounding`, `paper_writer_pse`, `claim_format_reexport`. Each obeys the single **Audit-loop scoping** rule and Loop Registry in CLAUDE.md (cap, reset scope, and FAIL route are declared there; the orchestrator reads the cap from `loops.<id>.cap`, never hard-codes it). Three empirical-specific notes the generic rule and registry do not by themselves make obvious:
- **Stage 3a step 7.5 asymmetry (exception 1 to auto-reset).** `data_integrity` and `method_check` audit different artifacts (cached data vs. estimation code) and re-fire on different loops. When one FAILs substantively and its artifact is redesigned, the *sibling* loop resets (its inputs changed) while the FAILing loop is left as-is (it is escalating, not retrying): a substantive data FAIL zeros `loops.method_check` but not `loops.data_integrity`, and the method-checker FAIL mirror zeros `loops.data_integrity` but not `loops.method_check`. See `docs/stage_3a_empirical.md` step 7.5.
- **The three claim-pipeline loops share one artifact: the claim set.** `claim_grounding`, `paper_writer_pse`, and `claim_format_reexport` are all scoped to the current claim set (`paper_claims.json` + `paper_source_map.json`), so any event that changes the claim set — a `paper-writer` PSE re-fire, a `claim-enumerator` ENUMERATOR-DRIFT re-fire, or a fresh Stage 5 pass after a Gate 5 major revision — zeros all three at once per the generic rule. They are otherwise independent: format re-export routes to the empiricist, grounder errors to the grounder, paper-side errors to paper-writer, so no loop consumes another's budget. `paper_writer_pse` is a plain consecutive-cycle counter (no set-similarity metric): it increments on every PAPER-SIDE-ERROR verifier REVISE and resets when the claim set changes.
- **`claim_format_reexport` keeps its VERIFIER-LIMITATION routing class.** The `format-unsupported` classification (a real value living in a non-parseable file, kept structurally disjoint from `pse_claim_ids` / `paper_side_error_count`, routed to the empiricist to re-export as JSON — never to paper-writer to drop) is the substance of this loop and is unchanged; only its cap (2) and reset fold into the generic rule. This class is the fix for the field-report failure where format-blind verifier failures were miscounted as fabrications and routed to drop real numbers. See `docs/stage_5.md` step 5a and `claim-verifier`.
