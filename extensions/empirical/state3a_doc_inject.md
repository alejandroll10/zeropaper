**`identification_plan_revision_round`** (this run has `--ext empirical`)**:** Counts identification-auditor REVISE rounds on the current empirical plan (Stage 3a step 3). Increments on each `identification-auditor` REVISE verdict that triggers a plan re-write; resets to 0 on (a) PASS, (b) FAIL routing to a different strategy from the menu, (c) entry to a new Stage 3a pass on a revised theory (per `docs/stage_3a_empirical.md` "Re-fire on theory revision"). **Hard cap: 3.** On the 4th REVISE, the orchestrator treats the plan as FAIL and routes per the FAIL branch of step 3. Without this counter the cap is unenforceable across multi-session runs.

**`data_integrity_round`** (this run has `--ext empirical`)**:** Counts data-integrity-auditor / data-selection-auditor REVISE rounds on the current cache build (Stage 3a step 7.5, fired in parallel after empirics-auditor PASS). Increments on each cycle where either auditor returns REVISE and the empiricist patches the data-construction code; resets to 0 on (a) both auditors PASS, (b) any auditor FAIL routed to data-layer redesign and re-execution, (c) entry to a new Stage 3a pass on a revised theory. **Hard cap: 3.** If `data_integrity_round >= 3` on entry to a fresh REVISE cycle (i.e., a 4th REVISE would be required from either auditor), the orchestrator treats the round as FAIL per the FAIL branch of step 7.5. Without this counter the cap is unenforceable across multi-session runs.
