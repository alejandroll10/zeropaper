5a. **Claim grounding (three-agent pipeline; `--ext empirical`).** Marker absence is not the same as evidence — paper-writer can author plausible-looking numbers that no empiricist output backs. Three agents in sequence close that gap by enumerating every numerical claim, matching each to a source, and programmatically verifying file:field:value resolution.

   a. **Enumerate.** Launch `claim-enumerator` on `paper/sections/*.tex`, `paper/main.tex`, and `paper/internet_appendix.tex` if populated. Output: `output/stage5/paper_claims.json` — one entry per numerical claim (coefficient, SE, p-value, t-stat, sample size, percentage, ratio, count, dollar amount, basis point) with `claim_id`, `paper_location` (file:line), raw value, and surrounding context. Deterministic regex pass.

   b. **Ground.** Launch `claim-grounder` with `output/stage5/paper_claims.json` and the empiricist's outputs under `output/stage3a/`. For each enumerated claim, locate the source and emit `{claim_id, file, field_path, cited_value}` in `output/stage5/paper_source_map.json`. The grounder may cite only parseable sources (JSON or LaTeX tables): a claim whose value exists only in a non-parseable file (CSV/parquet/pickle/etc.) is tagged `NEEDS_REEXPORT` (the empiricist must re-export it as JSON), and a claim with no source anywhere is tagged `NEEDS_EMPIRICIST`. Grounder must produce exactly one source-map entry per enumerator entry — coverage must equal 100%.

   c. **Verify.** Launch `claim-verifier` (Bash) with both files. Verifier checks, per entry: (i) source-map entry count equals enumerator count; (ii) cited file exists; (iii) field path resolves; (iv) cited value matches paper text within rounding tolerance. Outputs: `output/stage5/claim_verification.md` (human-readable) AND `output/stage5/claim_verification_summary.json` (machine-readable: `verdict`, `enumerator_drift`, `grounder_error_claim_ids`, `pse_claim_ids`, `needs_empiricist_claim_ids`, `verifier_limitation_claim_ids`, `failure_index`). Each failure is tagged GROUNDER-ERROR (coverage shortfall, typo'd path resolvable in file, cited-vs-source mismatch, invalid-derivation-tag), PAPER-SIDE-ERROR (file missing, value mismatch, `[NEEDS EMPIRICIST]` entries, tolerance-undefined, derivation-invalid), or VERIFIER-LIMITATION (format-unsupported — the cited file exists but is not JSON/LaTeX, so the value is real but unparseable; includes the grounder's clean `NEEDS_REEXPORT` entries — a `NEEDS_REEXPORT` carrying a stray `derivation` tag is reclassified to GROUNDER-ERROR by the verifier's hygiene check first). The three classes are mutually disjoint, and `format-unsupported` is deliberately kept out of `paper_side_error_count` so a format-blind failure is never miscounted as a fabrication. The orchestrator reads the JSON summary for routing decisions and counter updates; the markdown is for human review.

   **Routing on REVISE:**
   - **ENUMERATOR-DRIFT (root-level warning, fires before per-claim routing)**: verifier's independent regex re-count of the LaTeX exceeded `paper_claims.json:total_claims` by more than 2%. Re-fire `claim-enumerator` (it re-runs the regex pass and re-emits `paper_claims.json` with stable IDs preserved for surviving claims). Then re-fire `claim-grounder` on the updated claim set, then re-run the verifier from the top. This branch resets `claim_grounding_round` and `claim_format_reexport_round` to 0 (a changed claim set is a fresh grounding cycle) and does not consume a grounder cap round. Handle ENUMERATOR-DRIFT first when present, before the per-claim GROUNDER-ERROR / PAPER-SIDE-ERROR triage below.
   - **GROUNDER-ERROR failures**: re-fire `claim-grounder` with the verifier's failure list (coverage shortfall, typo'd field path resolvable in file, cited-vs-source mismatch, invalid-derivation-tag). Increment `pipeline_state.json:claim_grounding_round`. **Hard cap: 3 grounder rounds on the same claim set.** If `claim_grounding_round >= 3` and the verifier still returns GROUNDER-ERROR failures on the same claim set, halt for operator routing — three rounds without convergence indicates either a broken enumerator pattern or a structural mismatch between paper claims and empiricist output naming that an operator must adjudicate. The halt is GROUNDER-ERROR-specific: PAPER-SIDE-ERROR failures in the same verifier report still route to paper-writer per the next bullet.
   - **PAPER-SIDE-ERROR failures**: re-fire `paper-writer` with the verifier's failure list as input. Paper-writer follows the existing step-5 marker-scan procedure: drop each ungrounded claim, or re-fire `empiricist` per the Stage 3a re-fire if the missing number is load-bearing. After paper-writer revises, restart 5a from the enumerator (the claim set has changed). Reset `claim_grounding_round` and `claim_format_reexport_round` to 0. **PSE-cycle tracking:** before re-firing paper-writer, read the current PSE failure-claim-ID set from `output/stage5/claim_verification_summary.json:pse_claim_ids` (the machine-readable sibling the verifier writes alongside the markdown report) and compute the Jaccard overlap (intersection / union) against `pipeline_state.json:paper_writer_pse_claim_ids` (the prior PSE cycle's set). **First-cycle convention:** when the prior set is `[]` (no prior PSE cycle), Jaccard = 0 / |current| = 0, so the counter resets to 0 — the first PSE cycle never increments the cap. If overlap >= 0.5, increment `pipeline_state.json:paper_writer_pse_round`; otherwise reset it to 0 (substantively new failures — paper-writer is making progress). The `>=` boundary is deliberate: exactly half the claims persisting across cycles (e.g., 2/4 = 0.5 when paper-writer rotates one new failure in each cycle while two old ones persist) is not progress — without the `>=` boundary, an adversarial or confused paper-writer could evade the cap indefinitely by adding one new failure per cycle while keeping a fixed core. Then overwrite `paper_writer_pse_claim_ids` with the current set. **Hard cap: 3.** If `paper_writer_pse_round >= 3` after incrementing, halt for operator routing — persistent non-convergence on substantially the same claims indicates an empiricist gap the loop is not closing or paper-writer authoring numbers it cannot source. On verifier PASS, reset both `paper_writer_pse_round` to 0 and `paper_writer_pse_claim_ids` to `[]`.
   - **VERIFIER-LIMITATION failures (`format-unsupported`)**: the cited value is real but lives in a file the verifier cannot parse (CSV/parquet/pickle/etc.), or the grounder tagged it `NEEDS_REEXPORT`. Re-fire `empiricist` to re-export the cited value(s) named in `verifier_limitation_claim_ids` as JSON (Stage 3a re-fire procedure, directing output to a versioned `output/stage3a/*.json`), wait for the file and an empirics-auditor PASS, then re-fire `claim-grounder` on the same claim set (it now finds the JSON and cites it as `GROUNDED`), then re-run the verifier. Do **NOT** route these to paper-writer and do **NOT** drop the claims — the numbers exist; only the format is wrong. Increment `pipeline_state.json:claim_format_reexport_round`. **Hard cap: 2.** If `claim_format_reexport_round >= 2` and `format-unsupported` failures persist on the same claim set, halt for operator routing — two rounds without the empiricist producing a parseable JSON for a value it has already computed indicates a deeper output-pipeline problem (e.g., a value that cannot be re-derived, or an empiricist that keeps re-emitting the wrong format) that an operator must adjudicate. This branch does not touch `claim_grounding_round` or the PSE counters; format re-export is independent of the grounder-typo and paper-side loops. Like `claim_grounding_round`, `claim_format_reexport_round` is scoped to a fixed claim set: it resets to 0 not only on verifier PASS but also on (b) any `paper-writer` PSE re-fire, (c) any `claim-enumerator` ENUMERATOR-DRIFT re-fire, and (d) entry to a fresh Stage 5 pass after a Gate 5 major-revision — each changes the claim set, so the stale cap budget must not carry over to a new set's re-export problem.
   - **Mixed classes (GROUNDER-ERROR and PAPER-SIDE-ERROR in the same verifier report)**: handle GROUNDER-ERROR first (cheaper, no paper edits); on grounder PASS, re-run the verifier and address any remaining PAPER-SIDE-ERROR class. If `claim_grounding_round >= 3` AND PAPER-SIDE-ERROR is also present, halt the GROUNDER path only and route the PAPER-SIDE-ERROR failures to paper-writer (paper-writer's revision may dissolve the GROUNDER-ERROR claims entirely, since the claim set changes on re-write). When VERIFIER-LIMITATION is also present, handle it independently of both (it routes to the empiricist, not the grounder or paper-writer) — the empiricist re-export, grounder re-fire, and paper-writer re-fire can proceed without ordering constraints between the three classes, though re-running the verifier after each fix keeps the report current.

   Verifier PASS resets `claim_grounding_round` and `claim_format_reexport_round` to 0 and unblocks step 6. Never let a draft ship with verifier REVISE outstanding. Empirics-auditor at Stage 3a audits code/results, not paper claims — do not route GROUNDER-ERROR or PAPER-SIDE-ERROR claim failures back to it for adjudication. (This is not in tension with the VERIFIER-LIMITATION loop above: the empirics-auditor PASS in that loop is the standard quality gate on the empiricist's *re-exported JSON output*, exactly as in any Stage 3a re-fire — it is not adjudicating the paper claim.)

6. **Early bib-verify.** Launch `bib-verifier` on the draft. Same procedure as Stage 8 (OpenAlex + WebSearch fallback). If fabrications or fix-needed cites are found, re-launch paper-writer to drop or correct them before referees see the draft. Stage 8 still runs near the end as the final cite-key check; Stage 9 (polish) then audits the prose-level claims about each cite.
7. **Build the PDF and verify the build.** This is the canonical build procedure — use it for every subsequent rebuild too (polish, referee-response revisions, post-pipeline edits), not just the first draft.
   - **Recipe:** build with `latexmk -pdf main.tex` (and again on `internet_appendix.tex` if it was populated). `latexmk` sequences `pdflatex` + `bibtex`/`biber` and re-runs to convergence on its own. **Never** hand-roll bare `pdflatex` passes — they resolve `\ref` but skip the bibliography, so every `\cite` renders undefined and the References section ships empty.
   - **Gate.** A build counts as clean only if all three hold (a passing `\ref` resolution is necessary but not sufficient — it does not cover `\cite` or layout):
     1. `grep -c 'Citation.*undefined' main.log` returns `0`.
     2. The References/bibliography renders — `main.bbl` is non-empty (`grep -c bibitem main.bbl` > 0) and a References section is present in the PDF.
     3. No bad overflow — LaTeX prints overflows as `Overfull \hbox (NNNpt too wide) ...`; confirm none exceeds 40pt. `awk -F'(' '/Overfull \\hbox/{split($2,a,"pt"); if (a[1]+0>40) print}' main.log` must return nothing (sub-40pt boxes are harmless and ignored).
   - If any check fails, fix it (run the full `latexmk` recipe; correct cite keys or `references.bib`; fix the offending table/float) and rebuild before committing. Do not report the build as clean on the strength of `\ref` resolution alone.
8. Commit: `pipeline: stage 5 — paper draft written`
