5a. **Claim grounding (three-agent pipeline; `--ext empirical`).** Marker absence is not the same as evidence — paper-writer can author plausible-looking numbers that no empiricist output backs. Three agents in sequence close that gap by enumerating every numerical claim, matching each to a source, and programmatically verifying file:field:value resolution.

**Bypass recording (default mode too).** Skipping this verification (enumerate/ground/verify), shipping a draft with verifier REVISE outstanding, or running any of its three agents' tasks via a substitute is a core bypass *unless this doc sanctions it* — record a `gate-skipped` / `agent-substituted` row in `process_log/degradation_ledger.md` before continuing (`docs/core_bypass.md`).

   a. **Enumerate.** Launch `claim-enumerator` on `paper/sections/*.tex`, `paper/main.tex`, and `paper/internet_appendix.tex` if populated. Output: `output/stage5/paper_claims.json` — one entry per numerical claim (coefficient, SE, p-value, t-stat, sample size, percentage, ratio, count, dollar amount, basis point) with `claim_id`, `paper_location` (file:line), raw value, and surrounding context. Deterministic regex pass.

   b. **Ground.** Launch `claim-grounder` with `output/stage5/paper_claims.json` and the empiricist's outputs under `output/stage3a/`. For each enumerated claim, locate the source and emit `{claim_id, file, field_path, cited_value}` in `output/stage5/paper_source_map.json`. The grounder may cite only parseable sources (JSON or LaTeX tables): a claim whose value exists only in a non-parseable file (CSV/parquet/pickle/etc.) is tagged `NEEDS_REEXPORT` (the empiricist must re-export it as JSON), and a claim with no source anywhere is tagged `NEEDS_EMPIRICIST`. Grounder must produce exactly one source-map entry per enumerator entry — coverage must equal 100%.

   c. **Verify.** Launch `claim-verifier` (Bash) with both files. Verifier checks, per entry: (i) source-map entry count equals enumerator count; (ii) cited file exists; (iii) field path resolves; (iv) cited value matches paper text within rounding tolerance. Outputs: `output/stage5/claim_verification.md` (human-readable) AND `output/stage5/claim_verification_summary.json` (machine-readable: `verdict`, `enumerator_drift`, `grounder_error_claim_ids`, `pse_claim_ids`, `needs_empiricist_claim_ids`, `verifier_limitation_claim_ids`, `failure_index`). Each failure is tagged GROUNDER-ERROR (coverage shortfall, typo'd path resolvable in file, cited-vs-source mismatch, invalid-derivation-tag), PAPER-SIDE-ERROR (file missing, value mismatch, `[NEEDS EMPIRICIST]` entries, tolerance-undefined, derivation-invalid), or VERIFIER-LIMITATION (format-unsupported — the cited file exists but is not JSON/LaTeX, so the value is real but unparseable; includes the grounder's clean `NEEDS_REEXPORT` entries — a `NEEDS_REEXPORT` carrying a stray `derivation` tag is reclassified to GROUNDER-ERROR by the verifier's hygiene check first). The three classes are mutually disjoint, and `format-unsupported` is deliberately kept out of `paper_side_error_count` so a format-blind failure is never miscounted as a fabrication. The orchestrator reads the JSON summary for routing decisions and counter updates; the markdown is for human review.

   **Routing on REVISE:**
   - **ENUMERATOR-DRIFT (root-level warning, fires before per-claim routing)**: verifier's independent regex re-count of the LaTeX exceeded `paper_claims.json:total_claims` by more than 2%. Re-fire `claim-enumerator` (it re-runs the regex pass and re-emits `paper_claims.json` with stable IDs preserved for surviving claims). Then re-fire `claim-grounder` on the updated claim set, then re-run the verifier from the top. A changed claim set is a fresh artifact, so per the generic Audit-loop scoping rule the three claim-set loops (`loops.claim_grounding`, `loops.paper_writer_pse`, `loops.claim_format_reexport`) all start at 0 on this branch; it does not consume a grounder cap round. Handle ENUMERATOR-DRIFT first when present, before the per-claim GROUNDER-ERROR / PAPER-SIDE-ERROR triage below.
   - **GROUNDER-ERROR failures**: re-fire `claim-grounder` with the verifier's failure list (coverage shortfall, typo'd field path resolvable in file, cited-vs-source mismatch, invalid-derivation-tag). Increment `loops.claim_grounding.round`. If `loops.claim_grounding.round >= loops.claim_grounding.cap` and the verifier still returns GROUNDER-ERROR failures on the same claim set, halt for operator routing — rounds without convergence indicate either a broken enumerator pattern or a structural mismatch between paper claims and empiricist output naming that an operator must adjudicate. The halt is GROUNDER-ERROR-specific: PAPER-SIDE-ERROR failures in the same verifier report still route to paper-writer per the next bullet.
   - **PAPER-SIDE-ERROR failures**: re-fire `paper-writer` with the verifier's failure list as input. Paper-writer follows the existing step-5 marker-scan procedure: drop each ungrounded claim, or re-fire `empiricist` per the Stage 3a re-fire if the missing number is load-bearing. Increment `loops.paper_writer_pse.round` (a plain consecutive-cycle counter — no set-similarity metric). After paper-writer revises, restart 5a from the enumerator: the claim set has changed, so `loops.claim_grounding` and `loops.claim_format_reexport` start at 0 per the generic rule. If `loops.paper_writer_pse.round >= loops.paper_writer_pse.cap` after incrementing, halt for operator routing — persistent non-convergence indicates an empiricist gap the loop is not closing or paper-writer authoring numbers it cannot source. (`loops.paper_writer_pse` is scoped to the current claim set; it therefore also zeroes on an ENUMERATOR-DRIFT re-fire and on a fresh Stage 5 pass after a Gate 5 major revision, per the generic rule.)
   - **VERIFIER-LIMITATION failures (`format-unsupported`)**: the cited value is real but lives in a file the verifier cannot parse (CSV/parquet/pickle/etc.), or the grounder tagged it `NEEDS_REEXPORT`. Re-fire `empiricist` to re-export the cited value(s) named in `verifier_limitation_claim_ids` as JSON (Stage 3a re-fire procedure, directing output to a versioned `output/stage3a/*.json`), wait for the file and an empirics-auditor PASS, then re-fire `claim-grounder` on the same claim set (it now finds the JSON and cites it as `GROUNDED`), then re-run the verifier. Do **NOT** route these to paper-writer and do **NOT** drop the claims — the numbers exist; only the format is wrong. This VERIFIER-LIMITATION routing class is kept structurally disjoint from GROUNDER-ERROR and PAPER-SIDE-ERROR (`format-unsupported` is never counted into `paper_side_error_count` or `pse_claim_ids`) — that disjointness is the fix for the field-report failure where format-blind failures were miscounted as fabrications and routed to drop real numbers. Increment `loops.claim_format_reexport.round`. If `loops.claim_format_reexport.round >= loops.claim_format_reexport.cap` (cap 2, deliberately lower than the grounder/PSE caps) and `format-unsupported` failures persist on the same claim set, halt for operator routing — repeated rounds without the empiricist producing a parseable JSON for a value it has already computed indicates a deeper output-pipeline problem. This branch consumes none of the other loops' budgets (it routes to the empiricist, not the grounder or paper-writer); like the other claim-set loops it is scoped to the current claim set, so a `paper-writer` PSE re-fire, a `claim-enumerator` ENUMERATOR-DRIFT re-fire, or a fresh Stage 5 pass after a Gate 5 major revision zeroes it per the generic rule.
   - **Mixed classes (GROUNDER-ERROR and PAPER-SIDE-ERROR in the same verifier report)**: handle GROUNDER-ERROR first (cheaper, no paper edits); on grounder PASS, re-run the verifier and address any remaining PAPER-SIDE-ERROR class. If `loops.claim_grounding.round >= loops.claim_grounding.cap` AND PAPER-SIDE-ERROR is also present, halt the GROUNDER path only and route the PAPER-SIDE-ERROR failures to paper-writer (paper-writer's revision may dissolve the GROUNDER-ERROR claims entirely, since the claim set changes on re-write). When VERIFIER-LIMITATION is also present, handle it independently of both (it routes to the empiricist, not the grounder or paper-writer) — the empiricist re-export, grounder re-fire, and paper-writer re-fire can proceed without ordering constraints between the three classes, though re-running the verifier after each fix keeps the report current.

   Verifier PASS resets the claim-set loops (`loops.claim_grounding`, `loops.paper_writer_pse`, `loops.claim_format_reexport`) to 0 and unblocks step 6. Never let a draft ship with verifier REVISE outstanding. Empirics-auditor at Stage 3a audits code/results, not paper claims — do not route GROUNDER-ERROR or PAPER-SIDE-ERROR claim failures back to it for adjudication. (This is not in tension with the VERIFIER-LIMITATION loop above: the empirics-auditor PASS in that loop is the standard quality gate on the empiricist's *re-exported JSON output*, exactly as in any Stage 3a re-fire — it is not adjudicating the paper claim.)

7. **Build the PDF and verify the build.** This is the canonical build procedure — use it for every subsequent rebuild too (polish, referee-response revisions, post-pipeline edits), not just the first draft.
   - **Recipe:** build with `latexmk -pdf main.tex`. `latexmk` sequences `pdflatex` + `bibtex`/`biber` and re-runs to convergence *within a single document* on its own. **Never** hand-roll bare `pdflatex` passes — they resolve `\ref` but skip the bibliography, so every `\cite` renders undefined and the References section ships empty. **When `internet_appendix.tex` was populated and the two documents cross-reference each other** (`\externaldocument` / xr-hyper), `latexmk` cannot resolve the cross-document `\ref`s on its own — each document reads the *other's* `.aux`, which does not exist until that document is compiled. Build to convergence across both: `latexmk -pdf main.tex` (seeds `main.aux`), then `latexmk -pdf internet_appendix.tex` (resolves the IA's cross-references to the main paper from `main.aux` and writes `internet_appendix.aux`), then `latexmk -pdf main.tex` **again** (resolves the main paper's refs into the IA from `internet_appendix.aux`). Skipping the final main pass is the usual cause of `Internet Appendix Section ??` shipping in the main PDF.
   - **Gate.** A build counts as clean only if all six hold (`\ref` resolution, `\cite` resolution, layout, a placeholder-free title page, and legible tables all matter — a clean build on any one of them is not sufficient):
     1. `grep -c 'Citation.*undefined' main.log` returns `0`.
     2. The References/bibliography renders — `main.bbl` is non-empty (`grep -c bibitem main.bbl` > 0) and a References section is present in the PDF.
     3. No bad overflow — LaTeX prints overflows as `Overfull \hbox (NNNpt too wide) ...`; confirm none exceeds 40pt. `awk -F'(' '/Overfull \\hbox/{split($2,a,"pt"); if (a[1]+0>40) print}' main.log` must return nothing (sub-40pt boxes are harmless and ignored).
     4. No unresolved `\ref` — an undefined cross-reference renders as a literal `??` in the PDF (a reader-facing defect a referee reads as sloppiness, and a desk-reject risk) and emits a `LaTeX Warning: Reference '...' undefined` to the log. `grep -c 'Reference.*undefined' main.log` must return `0` — and the same on `internet_appendix.log` when the IA was populated. This is a distinct warning class from check 1's `Citation.*undefined`, so check 1 does not cover it; every `??` in the PDF (including a cross-document `\externaldocument`/xr-hyper ref into the Internet Appendix) corresponds to one of these `Reference ... undefined` lines.
     5. No residual skeleton placeholders — the deployed skeleton ships template tokens that paper-writer must replace (`TITLE PLACEHOLDER`, `ABSTRACT PLACEHOLDER`; the `\author` ships pre-anonymized, not as a placeholder). An unreplaced token renders verbatim onto the title page — a literal `TITLE PLACEHOLDER` as the paper's title is the first thing a desk editor sees, a desk-reject-grade defect no other gate reads back. `pdftotext main.pdf - | grep -c PLACEHOLDER` must return `0` — and the same on `internet_appendix.pdf` when the IA was populated. **Confirm `pdftotext` exists before trusting that `0`:** run `command -v pdftotext >/dev/null || echo GATE-BROKEN` first, and treat `GATE-BROKEN` as a hard build failure, not a pass. This check is the one gate in the six that can *silently invert* — if `pdftotext` is not installed, the shell prints `command not found` to stderr, `grep` reads an empty pipe, and the check prints exactly the `0` that means "clean", so a paper whose title page reads `TITLE PLACEHOLDER` passes. Install `poppler-utils` (macOS: `brew install poppler`) rather than working around it; several other pipeline paths need it as well (the `arpipeline.sty` fingerprint readback, `--mode report` on a PDF-only submission, and the figure producers' `.png` rasterization). Case-sensitive on the literal uppercase token (the skeleton tokens are all-caps; this avoids false-tripping on legitimate lowercase "placeholder" prose), and run against the rendered PDF (not source) so comments and non-`\input`'d scaffolding cannot false-trip it.
     6. No illegibly-shrunk table — a wide results table wrapped in `\resizebox{\textwidth}{!}{<tabular>}` scales to exactly `\textwidth` and so can **never** emit an `Overfull \hbox` (it defeats check 3 by construction), yet ships in microscopic, unreadable font. `arpipeline.sty` (loaded by every paper) measures each `\resizebox`'s realized scale and, when it shrinks a table below the legibility floor (0.6× natural width), writes an `ARPIPELINE-SHRUNK` line to the log. `grep -c 'ARPIPELINE-SHRUNK' main.log` must return `0` — and the same on `internet_appendix.log` when the IA was populated. (Only table content is measured, so a legitimately down-scaled figure does not trip it; a narrow table stretched *up* to `\textwidth` is also fine and is not flagged.)
   - If any check fails, fix it (run the full `latexmk` recipe; correct cite keys or `references.bib`; fix the offending table/float; for an unresolved cross-document IA `\ref`, run the full cross-document build sequence from the recipe above — `main.tex` → `internet_appendix.tex` → `main.tex` — so each document's `.aux` exists before the document that references it is finalized; for a residual placeholder, fill the token with real content and rebuild; for an `ARPIPELINE-SHRUNK` table, re-typeset it legibly per the wide-table guidance — `\footnotesize`/`tabularx` with wrappable columns, a `\sidewaystable`/landscape, or relegate it to the Internet Appendix — rather than shrinking it with `\resizebox`) and rebuild before committing. Do not report the build as clean on the strength of one check alone.
