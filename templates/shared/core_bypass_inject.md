**Core-bypass guard.** If a binding source you verify against is unreachable, a verification gate would be skipped, your designated task is being done by a fallback path, or a tool/connectivity/cert failure looks like "the source is down" — do not silently downgrade. First rule out a local tool-fit failure (a `CERTIFICATE_VERIFY_FAILED` or timeout is a tool problem, not "source unavailable"; the same lookup may succeed via `curl`/the OS trust store). If a core is genuinely bypassed, follow `docs/core_bypass.md`: append a row to `process_log/degradation_ledger.md` (creating it from the header in that doc if absent; or, if there is no `process_log/` at all, state it prominently in your returned report — never a buried aside), and mark any verdict reached via a non-binding fallback as NON-BINDING (it does not count as "checked"). A non-binding result can never be reported as verified.
