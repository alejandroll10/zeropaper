# Stage 0: Problem Discovery

This procedure, including `loops.stage0_discovery`, applies to **unseeded discovery**. Seeded and faithful deployments enter through `seed_triage` and bypass Stage 0 question discovery, so they never consume this budget.

**Durable resume guard (evaluate before any entry reset):** use `stage0_discovery_phase` and `stage0_discovery_step` to resume in place; do not clear logs, reuse a launch permit, redo a completed routing decision, or infer progress from canonical files left by an earlier episode. Phase `entry_initializing` reruns the idempotent new-episode file reset below before publishing the episode marker. Phases `scan_charged` and `gap_search` require `stage0_discovery_last_counted_attempt == problem_attempt`; phases `cap_routing` and `promotion` are also resumable with a null last-counted marker because the cap-entry route launches no broad scan.

- `scan_charged`: `stage0_discovery_pending_scan` is an object containing the exact literature-scout `instruction` and its numeric `permit` (the just-committed `loops.stage0_discovery.round`). A scan is durable only when the final `discovery_e{E}/literature_map_broad_p{problem_attempt}.md` exists; literature-scout never writes that path directly. If it exists, it was atomically published after a successful worker return: restore the canonical copy if needed, set phase `gap_search` and step `select`, clear the pending payload, commit, and continue without launching. If it is absent, the prior permit is spent because the orchestrator cannot know whether that physical launch occurred before the crash; any permit-specific `.pending.md` is partial evidence, never a completion signal. If the counter is now at cap, preserve the pending payload, set phase `cap_routing`, step `null`, and `stage0_discovery_cap_context = "incomplete_scan"`, commit, and take the no-scan cap route below. Otherwise increment the counter, replace `permit` with the new round, and commit a fresh retry permit **before** re-launching from the unchanged instruction. Reconcile exactly one `[permit {permit}] {instruction}` line in `domain_log.md` by writing the revised whole log to a sibling temporary file and atomically renaming it; replace a partial/mismatched record for that permit rather than appending a duplicate, then launch. Never re-launch under the old permit.
- `gap_search`: restore the versioned broad map to the canonical path if needed, then obey the durable step rather than inspecting whether canonical outputs happen to exist. `select` runs Step 0b and commits a selected gap with step `characterize`; `characterize` runs Step 0c and commits either a return to `select` or step `pose`; `pose` runs Step 0d and commits step `review`; `review` runs Step 0e and commits step `route`; `route` applies the recorded referee verdict without relaunching an agent. If a complete current-contract `branch_manager_discovery_p{problem_attempt}.md` already exists for an exhausted scan, route its recorded verdict rather than relaunching branch-manager.
- `promotion`: the branch-manager selection is already committed. Do not relaunch it or change the selected near miss. Use the same explicit `characterize` → `pose` → `review` → `route` steps, advancing the state and artifact in one commit after each agent returns. A returning episode's canonical `literature_map.md`, `problem_statement.md`, and `question_review.md` are stale until their corresponding promotion step completes; their mere existence never advances the step.
- `cap_routing`: the run-global cap bound for one of the two durable `stage0_discovery_cap_context` values. `downstream_return` uses the returning question and its Stage 1/puzzle failure artifacts; `incomplete_scan` uses the preserved pending instruction plus all complete maps, gap/near-miss records, and partial evidence from the current episode. Reuse a complete current-contract branch-manager report for this exact context if present; otherwise finish that no-scan launch. Only `PROMOTE-NEAR-MISS` is legal. Atomically commit the selected gap, phase `promotion`, step `characterize`, `stage0_discovery_cap_context = null`, and a cleared pending payload before final characterization.

`entry` is the only phase that begins the entry reset hook below; `entry_initializing` resumes its new-episode branch. For scan-owning phases (`scan_charged`, `gap_search`) and `cap_routing` with context `incomplete_scan`, a mismatched attempt is invalid state: stop that session and repair state from committed history rather than guessing across attempts. `cap_routing` with `downstream_return`, and a promotion reached from it, may intentionally have no scan owner.

**On every Stage 0 (re-)entry (each begins a fresh problem; every `problem_attempt` increment routes through a Stage 0 entry, so this entry hook is the single authoritative reset site): reset the problem-scoped Stage-1 state in `pipeline_state.json`:**
- Before changing the problem/theory identity, retire every active Gate-3a feasibility receipt belonging to the abandoned problem with a non-empty reason. Then, in the same state commit, set `theory_attempt = 1` and `theory_version = 1`; set every acceptance-version field present in this deployment to `null` (`stage2b_theory_version`, `stage2_mechanism_version`, `stage2_design_version`, `stage3a_theory_version`, and `stage3b_theory_version`); and keep accepted report/receipt path pointers unchanged until their fresh cumulative replacements pass review. This is the mandatory fresh-theory identity reset from `core.md`, applied here explicitly because Stage 0 is the authoritative fresh-problem entry. A resumed new problem whose numeric counters again equal 1 may not reuse an old acceptance value of 1.
- Reset `regeneration_round` to `0` if non-zero. Regeneration is scoped to a single problem; a new problem starts with a clean slate.
- Reset every `loops.<id>.round` to `0` **except `loops.stage0_discovery.round`** (leave each `cap` unchanged), and reset `gate0_best_question_score` to `-1` (and ignore any stale `output/stage0/best_question*.md`). A fresh problem-discovery pass starts every ordinary audit loop clean: this is the problem-level application of the generic Audit-loop scoping rule and subsumes the per-loop resets for the problem-scoped loops (`gate0_revise`, `gate0_reject`, `idea`, `pivot`) as well as every downstream loop that has not yet run on this problem. `stage0_discovery` is the exception because it is the run-global runaway budget for broad scans; neither discovery re-entry, Stage 1 handoff, regeneration, nor a later return from downstream resets it. `gate0_best_question_score` snapshots the best question seen so far (see Step 0e routing).
- Start an empty `output/stage0/gap_log.md` for the fresh problem-discovery pass by writing an empty sibling temporary file and atomically renaming it over the log; never truncate it in place. The log records each gap that is **closed**, **no-stake**, **weak-stake**, or **rejected** so Step 0b does not re-pick it; it accumulates within this pass and survives a crash/resume on disk.
- If `stage0_discovery_episode_start_attempt` is `null`, this is the first entry of a new search for a scored question. First set `stage0_discovery_phase = "entry_initializing"`, clear its step/context/pending payload, and commit **without setting the episode marker**. While in `entry_initializing`, atomically replace both `output/stage0/gap_log.md` and `output/stage0/near_miss_portfolio.md` with empty sibling temporary files; then, in one state commit, set `stage0_discovery_episode_start_attempt` to the current `problem_attempt`, set `stage0_discovery_gap_serial = 0` and `stage0_discovery_active_gap_id = null`, and restore phase `entry`. A crash before that final commit resumes `entry_initializing` and repeats the idempotent empty-file replacements, so a published episode marker can never coexist with a stale prior-episode portfolio. Use `output/stage0/discovery_e{E}/` for this episode's archives, where E is that saved start attempt. On discovery-driven re-entry the marker is already non-null, so preserve the portfolio, archive directory, and gap serial while clearing any completed active gap ID. A Stage 1 handoff sets the marker back to `null`; a later downstream return therefore begins a distinct episode and cannot feed stale maps to promotion.
- Set `stage0_discovery_phase` to `entry`, `stage0_discovery_step`, `stage0_discovery_cap_context`, and `stage0_discovery_active_gap_id` to `null`, and `stage0_discovery_pending_scan` to `null` as part of this fresh-entry reset.

**Binding pre-scan cap check for a new episode:** after the resume guard has ruled out a complete current scan, if `loops.stage0_discovery.round >= loops.stage0_discovery.cap` on entry, do **not** run Step 0a and do not charge another scan. Set `stage0_discovery_phase = "cap_routing"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = "downstream_return"`, and commit before launching `branch-manager` with context = `stage-0-discovery-exhausted`; mark this as a **downstream-return cap promotion with no current broad scan**, and save `output/stage0/branch_manager_discovery_p{problem_attempt}.md`. Inputs are the returning `problem_statement.md` and canonical `literature_map.md`, the Stage 1 or puzzle-triage artifacts whose failure caused this return, `output/data_inventory.md` if present, `domain_log.md`, and pipeline state. The branch-manager must return `PROMOTE-NEAR-MISS`, using the returning question plus its failure evidence as this episode's near miss; both re-scan verdicts are forbidden. Continue directly through the `PROMOTE-NEAR-MISS` route in Step 0b. A crash retry reaches the same phase through the `incomplete_scan` context above rather than this downstream-only route. These checks make 100 a run-global physical-launch ceiling: later downstream returns can reframe and independently score a question, but can never launch scan 101.

## Step 0a: Broad literature scan

**Agent:** `literature-scout`

1. Choose **one** domain to scan. The scope names starting points, not an exhaustive list — a domain it does not name is fine if it is genuinely in scope: {{DOMAIN_AREAS}}
2. Form the exact scout instruction `{domain} — fresh scan`, or `{domain} — corrected re-scan: {the correction}` when Step 0b routed you here. Name the domain the way you would to a colleague, and reuse earlier wording verbatim for a corrected scan.
3. Before launching the agent, increment `loops.stage0_discovery.round`, set `stage0_discovery_last_counted_attempt = problem_attempt`, set `stage0_discovery_phase = "scan_charged"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = null`, store `{"instruction": "{the exact instruction}", "permit": {round}}` in `stage0_discovery_pending_scan`, and commit `pipeline: stage 0 broad scan {problem_attempt} charged ({round}/{cap})`. The pre-scan check guarantees `round < cap` before this increment. A permit is consumed once committed: every physical launch or retry needs a distinct permit, so a crash can waste capacity but can never create an uncounted launch.
4. Reconcile exactly one `[permit {permit}] {instruction}` line in `output/stage0/domain_log.md`: write the revised whole log to a sibling temporary file and atomically rename it, replacing any partial/mismatched line for that permit rather than duplicating it. This permit-keyed log is never cleared. Launch literature-scout from the stored `instruction` and save its result to the permit-specific staging path `output/stage0/discovery_e{E}/literature_map_broad_p{problem_attempt}_permit{permit}.pending.md` (create the episode directory if absent). Only after the agent returns successfully, atomically rename that staging file to final `literature_map_broad_p{problem_attempt}.md`; never infer success from a `.pending.md` file. Copy the published final artifact to canonical `output/stage0/literature_map_broad.md`. Set `stage0_discovery_phase = "gap_search"`, `stage0_discovery_step = "select"`, and `stage0_discovery_pending_scan = null`.
5. Commit: `artifact: broad literature scan {problem_attempt}` (including the phase transition)

## Step 0b: Pre-select a gap

**Scan-exhausted check (do this first):** if `output/stage0/gap_log.md` already accounts for every gap from the broad scan so no untried gap remains, do **not** loop inside this pass.

- When `gate0_best_question_score >= 0`, apply the Step 0e REJECT-cap fallback now: restore `output/stage0/best_question.md` → `problem_statement.md` and `output/stage0/best_question_review.md` → `question_review.md`, set `stage0_discovery_last_counted_attempt`, `stage0_discovery_episode_start_attempt`, and `stage0_discovery_active_gap_id` to `null`, set `stage0_discovery_phase = "entry"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, set `current_stage = "stage_1"`, commit the artifacts and state together as `pipeline: gate 0 — cap reached, taking best question (score {gate0_best_question_score})`, and proceed to Stage 1 with it. Do not reset the run-global `loops.stage0_discovery.round` budget.
- When `gate0_best_question_score == -1` (no question was ever scored this pass), the versioned broad map already exists from Step 0a. Reuse a complete existing `branch_manager_discovery_p{N}.md`; otherwise launch `branch-manager` with context = `stage-0-discovery-exhausted`, output path `output/stage0/branch_manager_discovery_p{N}.md`, inputs = the current map + only this episode's archived `output/stage0/discovery_e{E}/literature_map_broad_p*.md` maps + `gap_log.md` + `domain_log.md` + `near_miss_portfolio.md` + `output/data_inventory.md` (if it exists) + `process_log/pipeline_state.json`. If `loops.stage0_discovery.round >= loops.stage0_discovery.cap`, tell it the cap is binding: it **must** return `PROMOTE-NEAR-MISS`; both re-scan verdicts are forbidden. Otherwise route on any of its three recommendations per `branch-manager.md` ("Stage 0 discovery-exhausted report"). Before beginning a `PROMOTE-NEAR-MISS`, write its canonical `gap_selection.md`, set `stage0_discovery_phase = "promotion"`, `stage0_discovery_step = "characterize"`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, and commit the selection and state together; only then launch final characterization. The run-global counter was charged before every physical broad-scout launch or retry, whether that scan eventually exhausted here or produced a scored question, and **regardless of the domain's name**. Step 0a selects one domain from an open variant scope, and a `-1` score means gap-scout killed every gap before `question-poser` ran. That is evidence about the scan, not proof that the field has no viable question; the terminal action is therefore autonomous promotion, never a claim of field-wide exhaustion and never an operator halt.

**`PROMOTE-NEAR-MISS` route (voluntary before the cap; mandatory at it):** read the committed branch-manager report's selected portfolio entry and salvage instruction, its returning-question reframe on a downstream-return cap promotion, or its evidence-grounded formulation from an incomplete-scan cap promotion. If entering fresh, write that selected gap/reframing to `output/stage0/gap_selection.md`, set `stage0_discovery_phase = "promotion"`, `stage0_discovery_step = "characterize"`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, and commit before launching anything; if resuming with phase `promotion`, preserve that committed selection and obey the step exactly. At `characterize`, launch `gap-scout` on the selection with the cited source artifacts plus the full branch-manager report. This is a final characterization pass, not another veto and not another broad-domain scan: save its closest-competitor, boundary, and stake analysis to canonical `output/stage0/literature_map.md` even if it still calls the original formulation `closed` or `no-stake`, set step `pose`, and commit both. At `pose`, tell `question-poser` to pose the strongest defensible question at the surviving boundary identified by branch-manager—not to repeat a result the literature map says is known—then set step `review` and commit with the new `problem_statement.md`. At `review`, run the ordinary independent `question-referee`, snapshot per Step 0e, set step `route`, and commit with the new `question_review.md`. At `route`, use that recorded verdict; never treat a stale canonical file as evidence a step completed. Promotion has a terminal routing override because there may be no current broad map with another gap: ADVANCE hands off normally; REVISE may increment the ordinary `gate0_revise` counter, set step `pose`, commit, and run another bounded poser/referee cycle; on REJECT (including a REVISE-cap conversion), first restore `output/stage0/best_question.md` → `problem_statement.md` and `output/stage0/best_question_review.md` → `question_review.md`, then take that best scored snapshot directly to Stage 1 rather than returning to gap selection or consuming `gate0_reject`. At either handoff, set `stage0_discovery_last_counted_attempt`, `stage0_discovery_episode_start_attempt`, and `stage0_discovery_active_gap_id` to `null`, set `stage0_discovery_phase = "entry"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, and set `current_stage = "stage_1"`; commit the final question artifacts and that state together before launching any Stage 1 agent, without resetting the run-global discovery budget. Thus every promoted question reaches Stage 1 after at most the bounded sharpening cycle even when cap routing launched no broad scan.

At step `select`, read the broad map + `output/data_inventory.md` (if it exists) + `output/stage0/gap_log.md` (if it exists — skip any gap already logged there as closed, no-stake, weak-stake, or rejected). Pick the most promising **untried** gap area, considering: **field stake** (is there a standing prior, consensus, or live debate so an answer would inform the field *whichever way it resolves* — or a consequential absence where no framework exists at all, so any answer changes practice or beliefs, Markowitz-style), gap size, tractability, data availability. Openness is necessary but not sufficient: among open gaps, prefer high field stake. Stake is not crowdedness: an untested assumption the field universally holds, or a consequential absence of any framework, is ideal (high stake, wide open); avoid a gap that is open only because no one would care about the answer. Stake is independent of difficulty: a hard gap that has resisted past attempts is still high-stake if a standing prior or consequential absence rides on the answer. Increment `stage0_discovery_gap_serial`, set `stage0_discovery_active_gap_id = "e{E}-g{stage0_discovery_gap_serial}"`, write the selection (a few sentences, naming that ID and the field stake) to `output/stage0/gap_selection.md`, set `stage0_discovery_step = "characterize"`, and commit the allocation, selection, and step before launching Step 0c. The active ID is stable across every crash/retry of this gap.

## Step 0c: Deep search on the gap

**Agent:** `gap-scout`

When `stage0_discovery_phase == "promotion"`, follow the dedicated promotion route above: a closed/no-stake characterization advances to `pose` instead of returning to `select`. The ordinary routing below applies only to phase `gap_search`.

1. At step `characterize`, launch gap-scout with the broad map, the gap selection, and the data inventory.
2. Save results to `output/stage0/literature_map.md` (this is the canonical map used downstream).
3. If the gap remains open, set `stage0_discovery_step = "pose"` and commit the map and state together: `artifact: deep literature map`.
4. If the gap-scout reports the gap is **closed**: use stable ID A = `stage0_discovery_active_gap_id`; copy `gap_selection.md` → `discovery_e{E}/gap_selection_{A}.md` and `literature_map.md` → `discovery_e{E}/literature_map_{A}.md`. Reconcile—not blindly append—exactly one `near_miss_portfolio.md` block keyed `[gap-id: {A}]` containing those paths, the domain and gap names, verdict `closed`, closest competitor, why the original question is closed, and the strongest boundary/reframing that might remain open. Likewise reconcile exactly one `gap_log.md` line keyed `[gap-id: {A}]` with status `closed`. Write each revised whole log to a sibling temporary file and atomically rename it over the canonical log. If a crash left only some outputs, rerun this reconciliation with the same A, replacing an incomplete/mismatched A record rather than allocating or appending another. Only after both logs and archives agree, set `stage0_discovery_active_gap_id = null` and `stage0_discovery_step = "select"`, and commit all artifacts and state together before returning to Step 0b. E is the current `stage0_discovery_episode_start_attempt`.
5. If the gap-scout reports **No** field stake (nothing rides on the answer either way): perform the same ID-keyed archive/log reconciliation as step 4, with verdict/status `no-stake`, what made the question low-stake, and the strongest nearby formulation on which a standing prior or consequential absence might ride; then clear the active ID, set step `select`, and commit before treating it as closed. If field stake is **Weak**: note it in `gap_selection.md`, reconcile the active ID's single `gap_log.md` line to status `weak-stake` by temporary-file + atomic rename, set step `pose`, and commit before continuing; retain the active ID until the question advances or is rejected. These records are append-only by stable ID within the current discovery episode: an existing ID is repaired/replaced in place, never duplicated.

## Step 0d: Pose the sharp question

**Agent:** `question-poser`

The question is the pipeline's generative primitive. Stage 0 owns it: the poser turns the validated gap into one sharp research question; Stage 1 will generate *approaches* that answer it. (This mirrors the Stage 1 generator→evaluator pairing — `question-poser` → `question-referee` here, `idea-generator` → `idea-reviewer` there.)

**Seeded / faithful mode bypass.** In `--seed` and `--faithful` runs the seed *is* the question, so `question-poser` (this step) and the Gate-0 `question-referee` vetting (Step 0e) are **not launched** — the `seed_triage` entry procedure (the "Stage: Seed Triage" section of your runtime doc, e.g. CLAUDE.md) back-fills `output/stage0/problem_statement.md` directly from the seed (faithful: reproducing the contract's question verbatim), and the pipeline enters at the appropriate downstream stage. Do not pose a fresh question from the literature map in seeded mode; that would let an unconstrained poser drift off the committed seed.

1. At step `pose`, launch `question-poser` with `output/stage0/literature_map.md` (the canonical deep map), `output/stage0/gap_selection.md`, and `output/data_inventory.md` (if it exists).
2. The agent poses **one** sharp question and pre-argues the four axes (important · unsolved · not-obvious · interesting-either-way) for the referee to vet. It saves `output/stage0/problem_statement.md`. Requirements the body enforces (re-check on return):
   - References the data inventory (if it exists)
   - Names the closest competitor identified by the gap-scout (or notes the gap-scout's missing-framework finding if there is no single competitor)
   - Argues **interesting either way** — names what the field learns under each plausible answer, flagging any dead branch
   - Does **NOT** specify a theoretical framework, mechanism, estimator, or candidate answer — choosing the approach is Stage 1's job, and pre-committing one here forecloses the search.
3. Set `stage0_discovery_step = "review"` and commit the question and state together: `pipeline: stage 0 — question posed`.

## Step 0e: Question Viability (Gate 0)

**Agent:** `question-referee`

This **replaces the former orchestrator-self-graded Gate 0** — the orchestrator scoring its own problem statement was the same self-referential evaluation flaw as #102, at the very top of the pipeline. The `question-referee` is search-grounded and independent: it confirms openness and non-obviousness against the actual literature, not the poser's say-so. (Bypassed in seeded / faithful mode — see the bypass note under Step 0d.)

1. At step `review`, launch `question-referee` with `output/stage0/problem_statement.md`, `output/stage0/literature_map.md`, and `output/data_inventory.md` (if it exists).
2. The agent scores the question on **important · unsolved · not-obvious** (three binding axes), with an **answerable** floor and an advisory **interesting-either-way** axis (a dead branch routes to REVISE, never REJECT — see the question-referee body), produces a 0–100 viability score and a verdict, and saves `output/stage0/question_review.md`.
3. **Snapshot the best question seen so far.** If this evaluation's viability score `N` is greater than `gate0_best_question_score` (initialized `-1`, so the first question always wins), copy `output/stage0/problem_statement.md` → `output/stage0/best_question.md` and `output/stage0/question_review.md` → `output/stage0/best_question_review.md`, and set `gate0_best_question_score = N`. Do this on **every** verdict (ADVANCE / REVISE / REJECT) before routing — "best seen so far across all gaps this pass" must include questions that were sharpened or rejected, not just the one that finally advances. (This is what makes the REJECT cap-5 fallback below executable: without the snapshot, each gap overwrites `problem_statement.md` and the best-scoring question is lost.)
4. Set `stage0_discovery_step = "route"` and commit the review, snapshot, and state together: `pipeline: gate 0 — question review ({verdict}, score {N})`.
5. At step `route`, route on the recorded verdict without relaunching the referee. **Phase check comes first:** if `stage0_discovery_phase == "promotion"`, apply the dedicated promotion override in Step 0b and do not consult the ordinary table below. In particular, promotion REJECT (including a REVISE-cap conversion) does not increment `loops.gate0_reject`, does not require `stage0_discovery_active_gap_id`, and hands the best scored snapshot directly to Stage 1 while clearing the promotion state as specified above. Only phase `gap_search` uses the ordinary table. The two ordinary caps below are tracked in `pipeline_state.json` so they survive a crash/resume (both are reset on every Stage 0 (re-)entry per the reset hook at the top of this doc):

| Verdict | Action |
|---------|--------|
| **ADVANCE** | The question is vetted. Set `stage0_discovery_last_counted_attempt`, `stage0_discovery_episode_start_attempt`, and `stage0_discovery_active_gap_id` to `null`, set `stage0_discovery_phase = "entry"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, and set `current_stage = "stage_1"`; commit the question artifacts and state together, then proceed to Stage 1 — `idea-generator` generates solution approaches to this fixed question. Do not reset the run-global discovery budget. |
| **REVISE** | Fixable sharpening. If `loops.gate0_revise.round >= loops.gate0_revise.cap`, do **not** revise again — treat this as REJECT (route to the REJECT row). Otherwise: increment `loops.gate0_revise.round`, set `stage0_discovery_step = "pose"`, and commit before re-launching `question-poser` with the referee's "required changes" section quoted in the prompt; then re-run this gate (0e) on the sharpened question. (Cap `loops.gate0_revise.cap` REVISE cycles per gap.) |
| **REJECT** | The question on this gap is not worth pursuing. Increment `loops.gate0_reject.round` and reset `loops.gate0_revise.round` to `0` (a new gap is a fresh question — the generic rule zeros its REVISE budget). Reconcile the active gap ID's single `gap_log.md` line to status `rejected` by whole-file temporary write + atomic rename. If `loops.gate0_reject.round >= loops.gate0_reject.cap`, stop searching: take the best question seen so far — restore the snapshot by copying `output/stage0/best_question.md` → `output/stage0/problem_statement.md` (and `best_question_review.md` → `question_review.md` for the log), set `stage0_discovery_last_counted_attempt`, `stage0_discovery_episode_start_attempt`, and `stage0_discovery_active_gap_id` to `null`, set `stage0_discovery_phase = "entry"`, `stage0_discovery_step = null`, and `stage0_discovery_cap_context = null`, clear `stage0_discovery_pending_scan`, set `current_stage = "stage_1"`, commit the restored artifacts and state together as `pipeline: gate 0 — cap reached, taking best question (score {gate0_best_question_score})`, and proceed to Stage 1 with it. Do not reset the run-global discovery budget. (The snapshot is guaranteed non-empty: step 3 above writes it on the first evaluation, so `gate0_best_question_score >= 0` by the time the 5th REJECT lands.) Otherwise set `stage0_discovery_active_gap_id = null` and `stage0_discovery_step = "select"`, commit the reconciled log and state, and return to Step 0b to pick the next most promising **untried** gap from the broad scan. |

Note: viability is governed by the three binding quality axes (important, unsolved, not-obvious); **interesting-either-way** is advisory and never drives REJECT on its own (a dead branch is a REVISE). **Answerable** is a floor, never a difficulty penalty — a hard question that needs a non-obvious approach is exactly what a top question looks like, and cracking it is Stage 1's job, not grounds to fail it here.
