# Stage 9: Polish

**Agents:** `polish-consistency`, `polish-formula`, `polish-numerics`, `polish-institutions`, `polish-equilibria`, `polish-identification`, `polish-bibliography`, `polish-prose`

This is the final substantive pass before the pipeline marks the paper complete. It runs *after* style edits (Stage 7) and *after* bibliography verification (Stage 8) — by this point the references file is clean, mechanical style is fixed, and the prose is in its final form. The eight polish agents read that final form with disjoint, focused checklists and produce structured fix lists. Together they catch the failure modes that referees flag immediately and that earlier checks systematically miss because those checks evaluated working theory/analysis sources rather than the rendered LaTeX, and because cross-section consistency, calibration sanity, institutional realism, identification coherence, and prose economy were never anyone's job.

Stage 9 hands off to Stage 10 (Lessons), which owns the `"status": "complete"` flag. The pipeline is not done until polish has either applied its fixes or judged that nothing actionable remains *and* the orchestrator has written the two lessons documents.

Never let a polish agent's absence be indistinguishable from a clean report. Commit nothing for this gate; it is a pre-triage integrity check.

3. **Aggregate via `triager`** (Stage 9 context — see the triager body's "Stage 9 output format" section). Launch the `triager` agent with the eight polish report paths as input and instruct it to write `output/polish_triage_r{N}.md`. The triager classifies each finding into three buckets per its Stage 9 rules (4, 5, and 6):
   - **Apply** — concrete fixes the agents identified with sufficient evidence (verbatim quote + suggested fix); criticals default to Apply, polish-formula criticals always Apply (rule 4 override), same-anchor findings across agents are deduplicated, and polish-prose cuts that conflict with another agent's keep/fix at the same anchor are dropped (rule 6).
   - **Investigate** — major-severity findings that lack a one-token fix and need paper-writer judgment, or criticals downgraded from Apply with a concrete justified conflict.
   - **Drop** — minor-severity findings that aren't one-token edits, plus any item the triager justifies dropping. Each drop has a one-line written justification.

   Before paper-writer passes, route any finding whose fix changes a computed value, result-bearing table cell, or plotted series to its producer. The producer must rerun its stage analysis/bundle/renderer and substantive review; paper-writer may then update only the surrounding prose/caption. Paper-writer never hand-fixes computed exhibits.

4. **Re-launch `paper-writer` in two sequential passes (not one).** Applying every triaged fix — formula corrections, numeric fixes, consistency rephrasings, structural relocations, *and* prose cuts — in a single invocation overloads one context and produces shallow edits on a long list; and a fresh prose-tightening pass should see the paper's *settled* structure, not edit prose that a later relocation is about to move. So split the already-deconflicted Apply/Investigate list across two **sequential** (never parallel — they edit the same `paper/sections/*.tex` files; concurrent writes race) `paper-writer` instances. In each prompt pass the *resolved* path with `{N}` substituted to the current round integer (e.g., `output/polish_triage_r1.md`, not the variable form), and tell the instance which pass it is and which rows it owns. Paper-writer's body has a "When re-invoked at Stage 9" section that handles Apply / Investigate rows.

   - **Pass 1 — structure + correctness.** This instance applies every row *except* polish-prose subtractive findings: all correction rows (polish-formula, polish-numerics, polish-consistency, polish-institutions, polish-equilibria, polish-identification, polish-bibliography) **and** the polish-prose additive/structural rows (`Disp. = add`/`rebalance` — items 10–13, including item-13 robustness relocations to the appendix/IA). Structure settles first so prose tightening in pass 2 reads the final layout. Instruct it: "Stage 9 pass 1 of 2: apply every Apply row whose `Disp.` is blank, `add`, or `rebalance`; skip every polish-prose row whose `Disp.` is `cut`, `compress`, or `rewrite` (pass 2 owns those). Run the cut-scan pre-processing pass only over rows you own."
   - **Pass 2 — prose, on the settled paper.** A second fresh instance applies the polish-prose subtractive findings (`Disp. = cut`/`compress`/`rewrite` — items 1–9, the whole subtractive family) against the structure pass 1 left. This matches polish-prose's existing subordination to every other agent. Instruct it: "Stage 9 pass 2 of 2: apply only the polish-prose Apply rows whose `Disp.` is `cut`, `compress`, or `rewrite`; the structural and correction fixes are already applied — read the current `paper/sections/*.tex`. Run the cut-scan pre-processing pass over your `cut`/`compress` rows first." Skip pass 2 entirely if no such rows exist.

   Each instance edits `paper/sections/*.tex` (and, for item-13 relocations, `paper/internet_appendix.tex`) to incorporate its Apply rows, drafts candidates for any Investigate rows it owns, and appends to the `## Investigate decisions` section of the triage file with one sentence per draft. After **each** pass returns and its Investigate decisions are accepted/revised/reverted, run `docs/results_evidence.md` with checkpoint `stage9-rN-p1` or `stage9-rN-p2` before launching the next mutation. Commit once after both passes: `paper: stage 9 polish — round r{N} fixes applied`.

The Stage 8 cap (`loops.bib_verify.round >= loops.bib_verify.cap`) does not apply.

If the round-2 triage still contained Apply criticals, ship the partial fix and note the unresolved findings under a "Known limitations" paragraph in `paper/sections/discussion.tex` before Stage 10 marks the pipeline complete.

## What each polish agent owns

| Agent | Owns | Does not own |
|---|---|---|
| polish-consistency | Cross-section contradictions, label↔object mismatches, headings vs. text, intro vs. later qualifications | Formula correctness; numerical reproduction |
| polish-formula | Re-derivation of every numbered equation; sign / subscript / abs-value errors paper-writer introduced | Numerical examples; whether prose contradicts the formula |
| polish-numerics | Recomputing every numerical claim; stock-vs-flow; normalized-vs-unnormalized; baseline IR feasibility | Formula correctness; institutional realism of the calibration |
| polish-institutions | Real-world facts (regulatory mechanisms, fee conventions, market sizes); faithful characterization of cited papers | Cite-key validity (bib-verifier); equation correctness |
| polish-equilibria | Multiple equilibria in fixed-point regions; LLN/continuum assumptions; reduced-form↔structural bridges; benchmark choice | Anything mathematically wrong with stated equilibria |
| polish-identification | Estimand-vs-claim alignment; diagnostics-vs-design coverage; cluster level vs. design level; identification.tex faithfulness; heterogeneity-population coherence; robustness vs. named failure modes; out-of-scope structural claims | Code correctness (empirics-auditor); design plan decisions (identification-auditor); theory mechanisms (polish-equilibria) |
| polish-bibliography | Per-citation prose-claim verification (FAITHFUL/APPROXIMATE/MISCHARACTERIZED/DECORATIVE) | Cite-key existence (bib-verifier) |
| polish-prose | **Subtractive:** repeated caveats, hedge stacking, abstract bloat, undefined acronyms, defensive framing, buried thesis sentences, section-opener resummary. **Additive/structural (items 10–13):** under-motivated intro (missing stakes / literature anchor), mechanism over-weight in empirical papers, broken through-line, mis-weighted caveat, over-stacked main-text robustness (relocate to appendix/IA) | Mechanical style (style agent); contradictions (polish-consistency); whether a caveat is correct |

The deliberate overlap between `polish-institutions` and `polish-bibliography` on egregious citation mischaracterization is fine — both will surface the same critical, the triager will dedupe by anchor. The deliberate subordination of `polish-prose` to every other polish agent (rule 5 precedence + rule 6 removal-vs-fix) is also fine — a prose *cut* that conflicts with another agent's keep/fix loses, because deletion eliminates the substrate the other agent was editing. **This subordination governs polish-prose's *subtractive* findings only.** Its additive/structural findings (items 10–13 — motivation, mechanism rebalancing, through-line bridge, caveat demotion, robustness relocation) carry `Disposition: add` or `rebalance` and are *not* cuts, so triager rule 6 (which fires only on a polish-prose *cut* at a shared anchor) does not apply to them; they route to `Apply`/`Investigate` on their own severity like any other agent's findings, and only the same-anchor *fix-vs-fix* precedence of rule 5 can demote them. Paper-writer applies them as small additions/rebalancing per its "Additive / structural polish-prose findings" note, not as deletions.

## Notes

- **Manual-mode chaining.** When a user runs polish manually (not via the autonomous orchestrator) they are their own orchestrator: pass `{N}=1` to all eight agents on the first chained run; if anything is re-run after paper-writer applies fixes, pass `{N}=2`. Agent bodies default to `N=1` when no value is supplied, so the round-1 path works out-of-the-box. Use this canonical manual sequence (round 1); every mutation checkpoint follows `docs/results_evidence.md` and reads its counter from `process_log/manual_evidence_state.json`:
  1. **Parallel launch:** `polish-consistency`, `polish-formula`, `polish-numerics`, `polish-institutions`, `polish-equilibria`, `polish-identification`, `polish-bibliography`, `polish-prose` — invoke all eight in one batch. Tell them to read `paper/main.tex`, its sections, and the IA when populated. For computed projects, enumerate `process_log/results_registry.json:active`; pass the exact reports, artifacts, and exhibits bound by those active receipts to the relevant numerics/consistency/identification agents. Manual mode has no `pipeline_state.json` result pointers and must not guess them from filenames. Pass identification menu/audit files when they exist.
  2. **Triager:** invoke `triager` with the prompt "Stage 9 context, loops.polish.round = 1; inputs are the eight output/polish_*_r1.md files; write output/polish_triage_r1.md".
  3. **Paper-writer (two sequential passes):** invoke `paper-writer` with "Stage 9 polish round, pass 1 of 2: read output/polish_triage_r1.md and apply every Apply row whose `Disp.` is blank, `add`, or `rebalance` (structure + correction fixes, incl. item-13 robustness relocations); skip polish-prose `cut`/`compress`/`rewrite` rows". Read the appended `## Investigate decisions` and accept/revert, then complete evidence checkpoint `manual-stage9-r1-p1`. Invoke a fresh `paper-writer` with "Stage 9 polish round, pass 2 of 2: apply only the polish-prose Apply rows whose `Disp.` is `cut`, `compress`, or `rewrite`, against the current section files"; skip pass 2 if there are no such rows. Read its decisions and, when it edits, complete checkpoint `manual-stage9-r1-p2` before continuing.
  4. **Style re-pass:** invoke `style` with the same prompt shape it used at Stage 7. Skip only if *neither* paper-writer pass in step 3 reported any edits. If style edits, complete checkpoint `manual-stage9-r1-style`.

  If the round-1 triage contained Apply criticals, repeat with `loops.polish.round = 2` (only the agents whose criticals were applied) and use the analogous `manual-stage9-r2-*` checkpoints; stop after round 2. Then rebuild the PDFs and invoke `table-auditor` on the final render before treating the manual chain as complete; any layout repair gets its own checkpoint. Finish with mandatory checkpoint `manual-stage9-final` and verify its paper receipt with `--rerender`. A prior Stage-5 PASS predates these edits and is stale.
- **Why polish is last, not earlier.** Style (Stage 7) sometimes silently changes a sentence that would have been a polish-consistency finding; bibliography verification (Stage 8) sometimes drops or reanchors cites that would have been polish-bibliography findings. Running polish *after* both means the agents are reading the final form of the paper. Style is then re-run at the end of Stage 9 (step 5) on the post-polish prose so mechanical violations reintroduced by polish edits don't ship. The cost is one wall-clock pass plus one fast style call per polish round.
- **Why a separate stage rather than another referee round?** Referees evaluate the paper's contribution and mechanism; they do not re-derive every equation, recompute every number, or look up every cited paper. The polish agents have narrow, mechanical-but-substantive checklists that referees skip. Running both gets coverage of both failure modes.
- **Why eight agents instead of one?** A single "find everything wrong with this paper" prompt produces shallow coverage of every category. Disjoint, focused prompts produce deeper coverage of each. The cost of eight parallel calls is one wall-clock pass.
- **What if a polish agent contradicts a referee request?** The triager judges. A referee request that survived Stage 6 has higher priority by default — drop the polish finding with a justification. Exception: a polish-formula critical (provably wrong equation) overrides any referee request, because the equation is wrong regardless of what the referee wanted.
- **Polish does not loop with referees.** If the polish agents surfaced a new fundamental issue (rare), commit the partial fix and flag it as a known limitation in the paper's discussion section. Do not reopen Stage 6.
- **Post-pipeline math-audit rule still applies.** Polish runs *inside* the pipeline. After Stage 10 marks `"status": "complete"`, any further proposition/lemma/corollary edits go through the post-pipeline math-audit procedure documented in `core.md`.
