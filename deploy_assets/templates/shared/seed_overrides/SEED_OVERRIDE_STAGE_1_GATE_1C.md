**Gate 1c BLOCKED** (either `BLOCKED-DIFFICULTY` or `BLOCKED-IMPOSSIBLE`): do NOT abandon the idea, and do NOT start a new Round of Stage 1. Report the blockage to `output/seed/prototype_blockage.md`, then try **one alternative formalization** (different state variable, different equilibrium concept, different time structure — anything that preserves what the seed pins). Whether or not the alternative clears, **the seed advances to Stage 2 carrying the blockage forward as a documented risk — Gate 1c never halts a seeded run.** The prototype is a portfolio screen; with a single seed contract (K=1) there is nothing to screen against, so a blocked prototype cannot be the point of terminal judgment. Stage 2 is where the derivation is attempted for real, and the genuine-impossibility judgment — with its ship-honest check — lives there (the Gate 2 seeded override in Stage 2).

**This supersedes the base Step-2 routing table (the `S = 0` / `S ≥ 1` cases above).** Under `seeded: true` the sole seed candidate is `winner: true` by construction. A `BLOCKED-IMPOSSIBLE` seed would leave `S = 0` under the base rule and trigger "start a new Round"; that must **not** happen — the seed is the contract and Stage 1 is not re-entered for a new idea. (A `BLOCKED-DIFFICULTY` seed is a survivor under the base rule, but with K=1 there is nothing to rank, so it is routed here rather than through the base tiebreak.) Route the seed candidate to Stage 2 **through Step 3's canonicalization, not a bare file copy:**

1. In `pipeline_state.json:stage1_candidates`, set the seed entry `winner: true, eliminated: false`. This **overrides base Gate 1c's `eliminated: true`** for a `BLOCKED-IMPOSSIBLE` seed (a `BLOCKED-DIFFICULTY` seed is not eliminated by the base rule anyway) — the seed is under active development downstream, not eliminated, so the state file must not mark it both eliminated and winner.
2. Run **Step 3 steps 4–5** on the seed candidate: copy `output/stage1/round_{N}/selected_idea_1.md` → `output/stage1/selected_idea.md`, `novelty_check_1.md` → `novelty_check_idea.md`, `idea_prototype_1.md` → `idea_prototype.md` (keep the per-round indexed files), and apply the Step-5 INCREMENTAL forwarding if the seed's Gate-1b verdict was INCREMENTAL.
3. Complete the normal Stage-1 close-out (Step 6 `pipeline_state.json` update and the Step-7 completion commit in theory-first; Steps 6–8 then Step 4 identification-design in empirical-first), then proceed to Stage 2.

The seeded re-formalization keeps the seed in place regardless of verdict: a blocked seed is re-formalized and carried into theory development, never triaged against a portfolio of alternative ideas and never terminally abandoned at prototype stage. If the Gate-1c verdict is `BLOCKED-IMPOSSIBLE`, still append its Negative-result section to `output/stage1/negative_results.md` before proceeding (per Gate 1c item 3), so it constrains the Stage-2 theory-generator, math-auditor, and self-attacker calls; a `BLOCKED-DIFFICULTY` does not propagate a Negative result (a difficulty stall is not a proven impossibility).
