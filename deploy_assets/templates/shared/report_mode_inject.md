## Report-mode context (`--mode report`)

This deployment referees an **external submission** — the body above was written for this pipeline's own drafts, and where it conflicts with this block, **this block wins**:

- **Inputs.** The manuscript is in `submission/` (read-only): `submission/main.tex` + `submission/sections/*.tex` + `submission/refs.bib` when LaTeX source is present, and/or `submission/paper.pdf`. Read what your launch prompt points you at. Pipeline artifacts named above — `paper/…`, `output/stage*/…` (theory drafts, implications, negative results, prior audit versions, exploration outputs), `process_log/pipeline_state.json` — do **not exist** here. Skip every step that reads or compares against them; the submission itself is the sole authoritative source.
- **Output.** Write your report to the exact `audits/<name>.md` path your launch prompt specifies — never to an `output/…` path named above. There is no `loops.polish.round` and no version numbering; write a single report. One exception: a helper *script* that hardcodes its own output path (e.g. `verify_bib.sh` always writes `output/bib_verification.md`/`.jsonl`; `codex-math` writes under `output/codex_*`) may write there — treat that as scratch, and copy the findings into your `audits/<name>.md` report yourself. The `audits/` file is the deliverable the synthesizer reads; a report left only in `output/` counts as missing coverage and halts the run.
- **PDF-only submissions.** If `submission/` has no LaTeX source, work from the PDF text (citations from the References section, equations and numbers from the typeset pages). Prepend a one-line `**Source not available — degraded check.**` note **only if the missing source actually weakens your tooling** — a shell-out that needs a `.tex` path (codex-math), a verifier that needs a `.bib` file, a citation enumeration that needs `\cite` keys, or a recomputation that needs the source code of a simulation or calibration solve. If your audit reads prose, claims, and typeset math the same either way, proceed normally with no note — a degraded-check note on an undegraded audit makes the synthesizer discount sound findings.
- **Never edit `submission/`.** If you need to render, extract, or annotate, copy into `process_log/` first.
- **Read the paper that's there.** Do not penalize divergence from this pipeline's house conventions (numbered-proposition style, internet-appendix layout, section naming, artifact schemas); evaluate the submission on its own terms.
- **Audience.** Your findings feed `report-synthesizer`'s editor-facing referee report. There is no scorer, no triager, no revision loop, and no re-fire: body language above about gates, rounds, or downstream pipeline consumers does not apply. Produce your findings once, in your standard format, at your standard severity calibration.
