### Paper-facing computation contract

Every computed result that could support the paper belongs in one canonical result bundle. Raw or high-dimensional outputs may stay in CSV, Parquet, JSONL, NetCDF, model checkpoints, or another natural format, but the bundle must declare and describe each such artifact. Formal theory objects — theorem numbering, proof constants, normalizations, and symbolic conditions — are not result records unless a script computes a paper-facing numerical implication from them.

The analysis entrypoint writes the bundle; it does not write final tables or figures. Its caller-supplied prose report path must appear in the run plan's `artifacts` array and as the matching described bundle artifact, and the analysis must freshly create it—an undeclared report stays inside the isolated workspace and is intentionally discarded. A separate renderer then reads only that bundle and its declared artifacts and produces every result-bearing LaTeX table and PDF/PNG figure. The renderer may format, select declared rows, and plot declared data; it must not read raw inputs, refit a model, query a service, or carry hard-coded numerical cells/series. This separation is binding: the saved result bundle must be sufficient to recreate the exhibits.

Before analysis, write the supplied `RESULT_PLAN` as a run-plan-v1 JSON object listing the exact `producer_code`, `producer_inputs`, `artifacts`, `renderer_code`, and `exhibits` paths the run will use. Keep every result-owned plan, bundle, receipt, artifact, and exhibit outside the audit-only `output/evidence/` namespace. Also set `provider_credentials` to the smallest required array chosen from `OPENAI_API_KEY`, `UF_API_KEY`, `DEEPINFRA_TOKEN`, and `LOCAL_LLM_API_KEY`; use `[]` unless this producer actually calls that provider. The trusted runner imports only those selected keys from the exported environment or project `.env`; unselected provider keys never reach the process, `.env` is never mounted, and renderers receive none. First copy every mutable pipeline document the computation reads—plans, implications, audit feedback, current reports—into the fresh attempt's `INPUT_SNAPSHOT_DIR`; the analysis reads and declares those immutable copies, never the canonical file that a later retry may revise. Stable raw datasets may remain at their original paths. Run both entrypoints through `code/utils/results_pipeline/results_pipeline.py` using the exact paths specified below. The analysis process receives `RESULTS_BUNDLE_PATH`; the renderer receives that bundle path plus an absolute `RESULTS_EXHIBIT_ROOT` staging directory and must create each declared exhibit at `Path(RESULTS_EXHIBIT_ROOT) / <project-relative-exhibit-path>`. Pass the prose report path as an explicit analysis-command argument. The utility snapshots plan/code/inputs before execution, requires the resulting bundle to match the plan exactly, records the actual commands, and hashes all declared evidence. Never hand-edit a rendered exhibit after its receipt is written.

Treat every active receipt's plan, declared code, inputs, outputs, recorded command, replacement relation, and exhibit bytes as immutable evidence. A re-fire uses fresh versioned plan, bundle, artifact, exhibit, and receipt paths; prefer versioned entrypoints too, and never overwrite an active or failed attempt's owned files. If genuinely shared code or a declared input changes, a fresh `run --supersedes <old-receipt>` may proceed only when that shared source is the old receipt's sole staleness; replace every affected active receipt before paper audit. The registry keeps the old run recorded while the replacement is rendered, verified, and substantively reviewed, and the new receipt preserves the exact `supersedes` relation after activation. Explicit `activate --receipt <new-receipt>` adds the accepted receipt without removing the old one, so a crash cannot invalidate or make the existing state pointer ambiguous. Atomically update the stage report/receipt pointers to the new active receipt, then explicitly run `retire --receipt <old-receipt> --reason "superseded by <new-receipt>" --superseded-by <new-receipt>`. Paper audit fails closed while an activated replacement and its declared predecessor are both active. If both runs remain active for combined coverage, omit `--supersedes` and retain both sets of byte-stable, disjoint evidence. A failed pending attempt must be explicitly retired with a non-empty reason before allocating another fresh attempt; never reuse its paths. Presentation-only renderer changes also use a fresh attempt; an active `render` invocation accepts only its exact recorded command and exact recorded bytes. Analysis and rendering run in default-deny workspaces containing only their declared project sources, a read-only neutral mount of the project venv/base interpreter, and fixed system runtime files; undeclared live-project paths are absent, stdin is EOF, and staged outputs must stay under `output/`. Producers receive only an allowlisted environment; provider-backed producers may still receive plan-selected API credentials and outbound network, while renderers receive neither provider credentials nor network environment. Only the trusted parent holds the lifecycle lock and publishes validated outputs. A separate lock-free supervisor kills and waits for the ordinary sandboxed process group if that parent dies; Linux payloads also run as PID 1 in a private namespace so normal exit cannot orphan background descendants. This bounds each execution to its own declared inputs instead of copying every historical receipt and prevents a failed child from changing lifecycle bytes or releasing serialization. Literal selected-provider credentials and percent-decoded proxy passwords of at least eight bytes are rejected from staged files, but deliberate encoded/network exfiltration, Linux renderer network access, hostile detached macOS grandchildren, and non-reflink large-input copies remain the explicitly tracked #267–#269 boundaries. Prose reports may interpret results for downstream agents, but they are not numerical sources of truth.

In command examples, uppercase path names denote values supplied in the launch prompt. Substitute their exact literal paths before execution; do not rely on undeclared shell variables.

Use run-plan version 1 from `code/utils/results_pipeline/run-plan-v1.schema.json` and bundle schema version 1 from `code/utils/results_pipeline/results-v1.schema.json`. Result IDs are stable lowercase semantic identifiers. Each result has a non-empty `description` and a `value`, a declared `artifact`, or both; `unit`, `uncertainty`, `display`, `selector`, and free-form object metadata are optional. Do not invent a discipline taxonomy. Each exhibit declares the result IDs it displays. Use `producer.reproducibility = captured` by default: the receipt binds the historical command and declared project evidence, not the interpreter/dependency closure. Use `exact` only when a complete content-addressed environment/lock manifest is itself a declared producer input and the auditor can validate that it covers the interpreter, imported packages/native libraries, and runtime flags; automatic multi-language environment capture remains tracked in #271. Use `bounded` only with a separately audited nondeterminism bound.
